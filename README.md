# AI 음성 판별 실험

훈련 1과 훈련 2를 한 웹앱에서 진행하는 익명 청취 실험입니다. 각 훈련에 20쌍(실제 음성 20개, AI 음성 20개), 총 40쌍과 80개 WAV를 사용합니다. 원본의 `-1`은 실제 음성, `-2`는 AI 음성입니다. 공개 파일명은 익명화되어 있고 정답 매핑은 이 저장소에 포함되지 않습니다.

## 실험 흐름

1. 참여 안내와 익명 데이터 저장 동의
2. 훈련 1: “높은 산에 올라가 맑은 공기를 마시며 소리를 지르면 가슴이 활짝 열리는 듯하다.”, 20쌍
3. 훈련 2: “바닷가에 나가 조개를 주으며 넓게 펼쳐있는 바다를 바라보면 내 마음 역시 넓어지는 것 같다.”, 20쌍
4. 각 쌍에서 A와 B를 모두 끝까지 재생한 후 AI 음성을 선택하고 1–5점 확신도를 표시
5. 제출 시 문항별로 Supabase에 저장. 다음 문항으로 이동. 정답 피드백은 없음

두 훈련의 순서는 고정(1 → 2)이고, 각 훈련 내 20쌍의 순서 및 개별 쌍의 A/B 위치는 참가자마다 무작위입니다. 완료할 때까지 같은 브라우저의 로컬 저장소를 이용해 재개할 수 있습니다.

## 데이터와 연구자 통계

`/#admin`은 연구자 전용 통계 화면입니다. Supabase Auth 이메일+비밀번호로 로그인한 뒤, 데이터베이스 RLS 정책에 허용된 연구자 계정만 응답을 볼 수 있습니다. URL 해시만으로는 통계에 접근할 수 없습니다.

- 완료 참가자 수, 미완료 세션 수, 참가자 단위 전체·훈련별 정확도와 95% 참가자 부트스트랩 구간
- 훈련 2와 훈련 1의 참가자 내 정확도 차이, 정오답별 평균 확신도, AI 위치별 정답률, A 선택 편향
- 확신도 1–5점 분포, 문항별 난이도·A/B 균형, 참가자별 요약
- 원자료 CSV (미완료 문항 포함), 완료 참가자 요약 CSV

주요 통계에는 정확히 40개의 서로 다른 문항을 제출한 세션만 포함합니다. 95% 구간은 참가자 재표집 2,000회에 기반한 기술적 구간이며, 모집단 추론이나 무작위표본 보장을 의미하지 않습니다. `response_ms`와 `a_plays/b_plays`는 브라우저 보고치로 실제 청취를 독립적으로 검증하지는 못합니다. 청취 완료 전 답변을 막는 동작은 클라이언트 측 장치입니다.

## 배포 및 보안

- `schema.sql`을 Supabase SQL Editor에서 실행하고, **공개하지 않는 별도 시드 SQL**로 40개의 실제/AI 경로를 `public.stimuli`에 등록합니다.
- `app.js`의 Supabase URL 및 publishable key는 공개 가능한 값입니다. 서비스 역할 키나 DB 암호를 이 저장소에 넣지 마세요.
- `public.stimuli`는 익명·인증 사용자 모두에게 읽기 권한이 없습니다. `submit_trial` RPC가 파일 경로를 검증하고 서버에서 정오답을 계산합니다. `public.responses`는 지정된 연구자 이메일로 인증된 세션만 조회할 수 있습니다.
- 관리자 통계는 Supabase Auth 이메일+비밀번호 로그인을 사용합니다. 연구자 이메일 계정은 Supabase Authentication Users에서 비밀번호가 설정되어 있어야 합니다.
- GitHub Pages는 `main` 브랜치의 루트(`/`)에서 정적 사이트로 배포합니다. GitHub Pages는 공개 저장소의 오디오 다운로드를 원천적으로 차단할 수 없으므로 음성의 공개 배포 권한을 확인하세요.

## 개인정보 및 방법론 메모

이름, 이메일, 연락처나 인구통계는 참가자로부터 받지 않습니다. 익명 코드와 문항별 응답만 저장하며, 연구자 로그인에 쓰는 이메일은 참가자 데이터가 아닙니다. 브라우저의 네트워크/개발자 도구나 API 호출을 기술적으로 조작하는 것을 완전히 방지할 수는 없으므로, 원자료 정제와 사전 등록된 제외 기준을 논문에 명시하는 것이 좋습니다. 저작권·초상권·연구윤리 동의 상태는 연구자가 별도로 확인해야 합니다.
